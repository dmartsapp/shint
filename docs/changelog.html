Changelog

What changed in every release, newest first.

Notable changes to shint, newest first. Versions follow semantic versioning; a change that scripts could notice is called out in bold. Full documentation: https://dmartsapp.github.io/shint/

Releases before v3.0.0 predate this file; see the GitHub releases and tags.

v4.2.1 - unreleased#

  • shint dns calls the field who answered nameserver= instead of server=, in text and JSON. server was a generic word for a command whose entire job is talking to nameservers; the dns authoritative side-note other commands print already uses nameservers (plural, a zone's delegation - a different, unrelated field). This is a change scripts could notice: the JSON key server on a dns query is now nameserver. Nothing else in dns's output changes, and no other command is affected. (Issue #53)
  • shint ip prints one line per interface, and its JSON has one flat object per interface. v4.2.0 printed an interface line and then one address line per address (each saying the address twice), and its JSON nested a five-field object per address inside the interface, so the answer to "what is this interface's address?" had to be assembled. Now everything about an interface is on one line - name=en0 state=up ipv4=[192.168.1.20/24] ipv6=[fe80::1c2d:3e4f:5a6b:7c8d/64,...] mac=... mtu=1500 flags=[...], a family with no address left out - and in one object: name, state, ipv4 and ipv6 (lists of strings such as "192.168.1.20/24", empty rather than null), mac, mtu, flags. The JSON shape and the text lines changed since v4.2.0, released the day before: the address lines and the addresses array are gone, and so are index, family, prefix, prefix_length and the per-address kind (shint cidr <address> says what kind an address is). -4/-6, ip <interface> and the exit statuses are unchanged. See ip. (Issue #52)
  • Release process: the Check workflow on main is now about three times faster when the suite already passed on the maintainer's machine, and CI can check that it did. make check takes about three and a half minutes on a runner, and it had been repeated there after every merge. make attest runs it locally, builds a report of the run (tree, time, tool versions, every stage, the battery's counts), signs the report with an SSH key and attaches it to the commit as a git note (refs/notes/checks). A fast-forward merge keeps commit ids, so on a push to main the Check verifies the note - signed by a key in .github/allowed_signers as it was before the push (a push cannot approve itself), for the tree that was checked out, every stage present and ok, recent - and runs make check-quick (the vulnerability check fresh, the CLI tests, the command-line groups of the black-box battery, the docs; about a minute) instead of everything. With no valid report - a direct push, a merge commit, a stale, edited, forged or someone else's report - it runs the whole suite as before, so a missing report costs time, never coverage. make hooks installs a pre-push hook that runs make attest when main or a release tag is pushed without one. The GitHub release page now shows the changelog's section for the tag under "What's new" instead of the commit message of whatever commit the tag is on (v4.2.0's page showed a later CI fix commit's message). The README Reconcile workflow, likewise, no longer waits for the release (it took up to an hour of idle runner time in its first draft). See the signed local check report.
  • Release process: main's README is now reconciled automatically after a release. It is written by hand, and after v4.2.0 it still said v4.0.4 was the newest release, and the donate line queued on a branch never landed. .github/scripts/readme-reconcile.py reads the README as it is and brings it in line with the release tags (Released, on the tag's date), the changelog (the text of a new row), the GitHub milestones (a coming release's sprint window) and the binary's --help (a command the Commands table lacks); it puts back what every README must have (the tagline's expansion, the badge row with a donate button, the support line) and warns about what it cannot know (a row that says Released with no tag, a release still planned although a later one shipped). A new tag-triggered workflow, README Reconcile, runs it after the tag (in under a minute; it does not wait for the release workflows) and opens a pull request for readme/main-vX.Y.Z - or an issue that links the branch, because this repository does not let Actions open pull requests - and never commits to main. By hand: make readme-reconcile TAG=vX.Y.Z. See README after a release.

v4.2.0 - 2026-09-21#

New commands ip and dns, the authoritative name servers shown wherever shint resolves a name, udp --hex for binary payloads, and the fixes for what the black-box test battery found in v4.0.5 and v4.0.6: crashes and overflows on bad flag values, a web that held whole downloads in memory, --count with --delay 0 running out of file descriptors, failures logged as OK, and a listen http that ignored broken requests.

  • Invalid flag values are usage errors (exit 2) instead of crashes, overflows or being waved through. udp --payload -1 (or 9223372036854775807) crashed with a stack trace; --payload must now be 0 to 65507 bytes, the most one UDP datagram carries, and --data at most 65507 (Issue #29). --timeout and --delay become a duration in nanoseconds, which overflows above about 292 years: --timeout 10000000000 used to make telnet, udp and ping fail at once with a misleading "i/o timeout", and --delay 9223372036854775807 was silently no delay at all. --timeout is now 1 to 86400 seconds and --delay 0 to 86400000 milliseconds (a day each, for every command; for listen, --timeout 0 to 86400), and a negative --delay is refused too (Issue #30). shint listen bogus and shint completion bogus printed the help page and exited 0; they now say unknown command "bogus" for "shint listen" and exit 2, and listen --count -1, accepted as "unlimited", is refused like it is on every other command (Issue #33). See Flags shared by every command.
  • listen http now logs and counts a request it could not serve. A request that net/http could not parse (GARBAGE, an oversized header, framing it could not read) was answered 400 but never logged and never counted, so a client sending garbage - exactly the case someone is diagnosing - left no trace and --count 1 waited forever for a "real" request. A client that stopped halfway through a request body was worse: it was logged as OK request ... status=404 bytes_sent=0, as if it had been answered. Both are now ERROR lines and count as a request: request rejected (with the status the client was answered, and the method and path when they were read) and request incomplete (nothing was answered, bytes_sent=0); with --json the event carries error (an additive field). A connection that sends nothing - telnet, nmap, a TCP health check - is still not a request. See listen. (Issues #34, #35)
  • New flag: shint udp --hex sends exact bytes. --data is text as typed, and a backslash escape such as \x00 reaches shint as four ordinary characters, so a binary probe - a DNS or STUN request, anything with a zero byte - could not be sent at all (udp --help said so since v4.0.4). --hex 00010203ff sends those five bytes; upper or lower case, with spaces or colons between the bytes if you like ("00 01 02 03 ff", 00:01:02:03:FF). An empty value, an odd number of digits, a character that is not a hex digit (a 0x prefix included) or more than 65507 bytes is a usage error (exit 2) that says what is wrong and sends nothing; --hex cannot be combined with --data, and --payload is ignored, as it is with --data. The log (sent=) and the JSON (bytes_sent) show how many bytes went out, and a reply is previewed escaped, as before. A real DNS query is shint udp 8.8.8.8 53 --hex "1234 0100 0001 0000 0000 0000 07 6578616d706c65 03 636f6d 00 0001 0001". The flag's help text no longer says binary payloads "cannot be sent yet". See udp. (Issue #46)
  • shint web no longer holds the whole response body in memory. Every response was read completely into memory even though nothing but --json -W shows it: a 300 MB download peaked at 662 MB (829 MB with --json), and pointing web at a multi-gigabyte file to see its speed could exhaust memory. The body is still read to its end - the byte counts, the timing and the check that it arrived whole need that - but counted and discarded as it arrives; only --json -W keeps it. See web. (Issue #28)
  • --count N --delay 0 no longer opens a socket per attempt, so a low descriptor limit no longer fails attempts that had nothing wrong. telnet, web and udp started every attempt at once, each holding a socket; where the process could open fewer files than there were attempts - a container, a CI runner, a script that ran ulimit -n 256 (Go raises the limit to the hard limit at start, so a normal shell is unaffected) - the surplus failed with too many open files and was reported as a failed check on the target: 3000 attempts under 256 descriptors lost 2379. Attempts now take a slot first: at most 500 run at once, fewer under a low descriptor limit (half of it), and the rest wait their turn (Ctrl+C while waiting ends the run as usual). nmap, whose fixed bound of 500 had the same problem against a host that drops packets, follows the same limit (max_in_flight on its first line says what it is). (Issue #31)
  • A failed check is logged as ERROR in two more places. udp printed OK probe closed and ping printed OK error sending request ... while the run exited 1; both are ERROR lines now, so "exit 1 means an ERROR line says why" holds for them too. --json is unchanged (udp's success is still false only when the probe itself errored). (Issue #32)
  • Every command that resolves a host name now shows who runs its DNS. After dns resolved, telnet, ping, web, nmap, udp, ntp and rdns print one line with the zone the name belongs to and its authoritative name servers - dns authoritative zone=example.com nameservers=[elliott.ns.cloudflare.com,hera.ns.cloudflare.com] time=49ms - and with --json the same is dns_lookup.authoritative (an additive field). NS records exist only at a zone's apex, so the name and each of its parents are asked at once through the same DNS engine as shint dns, and the closest zone that owns name servers is reported (www.github.com is reported as github.com: an alias does not borrow the zone of the name it points to, which the system resolver's own LookupNS would have got wrong). It is context, not a check: it never changes the exit status, prints nothing for an IP address, a single-label name or a name that does not resolve, is bounded by --timeout (at most three seconds) and dropped as soon as the closest zone is known, so it adds about 40 to 100 ms. It is the delegation as your resolver serves it, not an authoritative answer - shint dns @server shows the aa flag. See Who runs the DNS for this name. (Issue #44)
  • listen tcp logs a transfer as a few lines instead of one per read. A 20 MB upload printed 4,887 data received lines, one for every 4 KB read, and the one that mattered (connection closed ... bytes_received=20000000) was the last of them. Reads that arrive together are now one line, logged once the connection has been quiet for 100 ms or after 1 MiB, with reads=N saying how many it covered and the first read's preview; the same upload is 24 lines and the totals are exact. Data sent at separate moments is still a line each, a single read is logged exactly as before, echoing is not delayed, and --json still emits an event per read. See listen. (Issue #39)
  • Documented: shint web never uses a proxy, and --timeout does nothing for listen udp. HTTP_PROXY, HTTPS_PROXY and NO_PROXY have always been ignored - web connects directly to the address the name resolves to, which is what a reachability check should measure - but nothing said so, and behind a proxy a request that worked in curl timed out with no hint why. web --help, the web page and Troubleshooting now say it, and a test pins it. Likewise --timeout is an idle timeout for listen tcp and listen http connections but has no connection to act on for listen udp; the flag's help text and the listen page now say so. Behaviour is unchanged. (Issues #36, #40)
  • shint web understands a URL without a scheme properly, and says what is wrong with a bad one. 127.0.0.1:8080/status used to fail with only Invalid URL (and localhost:8080 was read as the scheme localhost); a URL without a scheme is now fetched over https:// - as a bare host name always was - so both work, and http:// is what to write for a plain-HTTP server. When an https:// request reaches a server that answers in plain HTTP, the failure now says so (the server speaks plain HTTP: use http:// in the URL). Anything but http and https (ftp://, file://), a URL with no host, an empty URL and the typo http:host are usage errors (exit 2) that name the problem, where ftp:// used to be a failed request (exit 1). See web. (Issue #38)
  • New command: shint dns <name> [type] [@server] - DNS lookups, like dig, in shint's format. Asks a DNS server for A, AAAA, CNAME, MX, NS, TXT, SOA, SRV, PTR or CAA records (a name without a type is asked for A and AAAA; an IP address is looked up in reverse) and shows the exchange - the server that answered, UDP or TCP, the response code, the header flags (aa marks an authoritative answer), the counts and the time - and one line per record with its TTL. @server (an address or a name, with an optional port) asks any server, including an authoritative one with --no-recurse; without it the servers this machine is configured with are asked in order, and one that does not answer is skipped with the reason shown. It is an ordinary unprivileged UDP query (EDNS, 1232 bytes) that is asked again over TCP when the answer is truncated (--tcp forces TCP); a reply counts only if it has this query's ID and question, so a forged or stray packet cannot answer it. A question that gets no record of the type asked - NXDOMAIN, no data, SERVFAIL, REFUSED, a malformed reply, no answer - is a failed check (exit 1) with its reason. The response code is lower case in the text log (noerror), because NOERROR would contain the text ERROR. Adds golang.org/x/net as a direct dependency (it was already used through go-ping). See dns. (Issue #43)
  • New command: shint ip - this machine's network interfaces and addresses. Lists every interface with its state (up/down), flags, MTU and hardware address, and each address with its prefix length and what kind of address it is (loopback, private, link-local, global, ... - the same words cidr uses); shint ip en0 shows one interface, -4/-6 list only that family's addresses. It reads the operating system's interface table and sends nothing, so it needs no network and no privileges, and it reads the same on Linux, macOS and Windows. A name that does not exist is a failed check (exit 1) that names the interfaces that do. See ip. (Issue #42)

v4.1.0 - 2026-09-21#

v4.1.0 was never released on its own: v4.2.0 superseded it, and everything in this section shipped in v4.2.0. "This release" below means v4.2.0.

New commands ntp, wol, rdns and cidr, web --timing, IPv4-only and IPv6-only checks, safer listener previews, a Go module path that go install accepts, and verified downloads: a SHA-256 file and a signed build attestation for every binary.

  • New flags -4/--ipv4 and -6/--ipv6: check IPv4 addresses only, or IPv6 addresses only. A name with both kinds of address is still checked over both by default, but on a machine with no IPv6 that made every dual-stack check fail (the reported case: a Linux host with IPv6 disabled, socket: address family not supported by protocol, exit 1 for a service that works over IPv4) and the only workaround was to look up and pass the IPv4 address. The flags work on telnet, ping, nmap, udp, web (they bind the HTTP client's own connection too), ntp and rdns; both together, or an address of the other family, is a usage error (exit 2). A failed IPv6 connect that is really this machine's lack of IPv6 now carries a hint pointing at -4. See IPv4 only, or IPv6 only. (Issue #23)
  • Ctrl+C shows the summary on the new commands too: ntp, rdns and wol stop, print the interrupted line and their done line (or the complete JSON document), drop an attempt still in flight, and exit 1, exactly as telnet, web and udp do since v4.0.5. See Stopping early. (Issue #24)
  • New command: shint ntp <server> - check this machine's clock against an NTP server. One SNTP query per resolved address (IPv4 and IPv6) reports the offset (server minus local, so a positive offset means this clock is behind), the network round trip, and the server's stratum, leap indicator and reference. A reply that cannot be trusted - it does not echo the request, the server says it is unsynchronized, a "kiss-o'-death" - is a failed query; --max-offset MS turns the offset into a pass/fail check. Unprivileged. See ntp. (Issue #19)
  • New command: shint wol <mac> - send a Wake-on-LAN magic packet. The 102-byte packet goes out as a UDP broadcast (--broadcast, default 255.255.255.255; --port, default 9). It cannot know whether the machine woke - Wake-on-LAN has no reply - and says so. IPv4 only, no privileges. See wol. (Issue #18)
  • New command: shint rdns <ip-or-host> - reverse DNS. Looks up the names an address maps back to (PTR records); a host name is resolved first and every address it resolves to is looked up, like every other command. An address with no PTR record is a failed check (exit 1). The in-addr.arpa / ip6.arpa name that was asked for is in the output, so it can be checked against dig -x. See rdns. (Issue #16)
  • New command: shint cidr <prefix>... - a subnet calculator, offline. Network, netmask, wildcard, first and last address, broadcast, address and usable-host counts and the kind of range, for IPv4 and IPv6; a bare address is a host route, /31 follows RFC 3021, and counts are exact decimal strings (IPv6 overflows 64 bits). See cidr. (Issue #17)
  • shint web --timing shows where the time went: DNS, connect, TLS, wait for the first byte and download, with one line per hop when a redirect is followed (a timing object per stat with --json). A reused connection shows connection=reused; a failed request still reports the time spent before it failed. Off by default - nothing changes without the flag. See web. (Issue #20)
  • The preview shown by listen tcp, listen udp and by udp (response_preview) now escapes what is not plain text. Printable text is unchanged; control characters and bytes that are not valid UTF-8 appear as \xNN (line breaks as \n), so a binary packet no longer garbles the terminal, a payload cannot pass an escape sequence to it, and a line break cannot forge a log line. (Issue #22)
  • The module path is now github.com/dmartsapp/shint/v4, so go install github.com/dmartsapp/shint/v4@latest works from this release on (it could not with the old path and v4 tags). Anyone importing lib or lib/handlers must change the import path; nobody is known to. Tags v4.0.0-v4.0.6 keep the old path. (Issue #15)
  • The test suite now compiles for Windows (it used syscall.Kill, which does not exist there): the three "runs until interrupted" listener tests use a small helper with a Unix and a Windows version, and are skipped on Windows. make vet now also vets for Windows, FreeBSD and Solaris, so a Unix-only test cannot slip in again. The shipped binaries were never affected; this is about running the tests. (Issue #13)
  • The tool's expansion is now "Simple Host INspection Toolkit" (shint = Simple Host INspection Toolkit). It appears in shint --help, the README and the documentation home page. The name shint, the binary, the repository, the image and every URL are unchanged.
  • The README gained a row of build-status badges (Lint, Vulnerability check, Build, Docker Hub, GHCR, Check) and a one-line link for supporting the project at the very bottom. Nothing else - no documentation page, no command output - mentions it.
  • New Check workflow: make check now runs after every merge to main (never for a branch, a pull request or a tag, and not when the push only changes .github/), so the test suite, lint, vulnerability check and workflow checks no longer wait for release day. It publishes nothing and files an issue if it fails. The trigger shape is enforced by the workflow-trigger check.
  • Verify your download: every release binary now has a SHA-256 checksum file and a signed build attestation. A release has 28 assets - the 14 binaries and a <binary>.sha256 file for each. sha256sum -c shint.linux.amd64.sha256 (Linux) or shasum -a 256 -c shint.darwin.arm64.sha256 (macOS) checks a download for damage; gh attestation verify shint.linux.amd64 --repo dmartsapp/shint proves it was built by this repository's release workflow from the release's commit (a keyless Sigstore signature: nothing to install but the GitHub CLI, no key to trust). Releases before v4.2.0 have neither. This is provenance, not operating-system code signing: macOS and Windows may still warn about an unknown publisher. See Verify your download.
  • The release workflow now creates the GitHub Release with softprops/action-gh-release@v3 (it was @v1, which actionlint flags as too old to run on current runners). The inputs used are unchanged. make workflows no longer ignores that warning. (Issue #12)
  • Release process: a README is scoped to its branch. A release branch's readme.md is a working page for that branch alone (milestone targets, bugs, changes) and is never merged into main; main's README tracks every milestone and release and is changed only on main. make release-check is a new release-day preflight that checks the branch is on top of main, readme.md matches main's, the version, dated changelog and release-commit message agree, there are no attribution trailers, and the tag is free. See Releases and tagging.
  • The issue that CI files when a check fails now carries the real URL of the failed run, the tag or branch and the commit. It is written by .github/scripts/write-ci-failure-issue.sh (with its own test) from values the workflow passes in; the static template file it replaces could not, because GitHub expands ${{ }} only in workflow files. Lint and Vulnerability Check use it too.

v4.0.6 - 2026-09-21#

A patch release that fixes two wrong answers - a check that reported success when it had not succeeded - and adds the test battery that found them, and a Slack message with the result of every release.

  • web no longer reports a response that ended early as a success. When the server closed the connection short of its Content-Length, reset it mid-body, or stalled until --timeout, shint web logged OK response status=200 and exited 0 ("success": true with --json) with however many bytes had arrived. It is now a failed attempt: an ERROR response incomplete line with the read error (unexpected EOF, connection reset by peer, or the timeout), "success": false, and exit status 1. A script that ran web against a server that cuts responses short saw 0 before and now sees 1 - the correct answer. (Issue #26)
  • ping no longer reports an unreachable host as reachable while another ping on the machine gets a reply. The ping library matched a reply to its request on the sequence number alone, and every ping's first request has sequence 1 and the same ICMP identifier. On macOS, and on raw sockets, an ICMP socket is handed every echo reply the host receives, so a ping to an address nobody answers succeeded with a neighbour's reply - nine runs in ten in the reproduction (shint ping 192.0.2.1 while shint ping 127.0.0.1 runs), and between two addresses of one host pinged in parallel. go-ping v2.0.1 gives every echo request its own identifier and accepts only the reply that carries it. Linux is unchanged: the kernel already delivers a ping socket only its own replies. A monitoring script that pings many hosts in parallel could have seen a dead host reported alive. (Issue #27)
  • The release pipeline now posts its result to Slack. A new sixth workflow, Notify Slack, starts with the tag, waits for the five release workflows and posts one message: whether everything passed, one line per workflow (binary build and release, vulnerability check, linting, Docker Hub image, GHCR image) with its duration and a link to its run, how many files the release has, what failed and in which step, and buttons for the release notes and the runs. It publishes nothing and changes nothing - if it fails, the release is unaffected. The webhook is the repository secret SLACK_WEBHOOK_URL: without it the job says so and succeeds, the script never prints it, and a test fails the build if a webhook URL is ever committed. See Slack notification.
  • A black-box test battery now runs with make test (and so make check and make test-full): 356 cases that drive the real binary against loopback servers that misbehave on purpose - truncated and reset responses, odd hosts, ports and flag values, malformed HTTP, signals, closed pipes, memory use - and judge exit status, output, JSON validity and timing. It found 15 issues (#26-#40); the two above are fixed in this release, and the cases for the 13 that are still open are listed in test/battery/known_issues.py and must keep failing until each is fixed, so the run tells you when a fix lands and when something new breaks. See Testing.

v4.0.5 - 2026-09-20#

  • Ctrl+C on a repeating check now shows the summary. shint web http://host/ --count 100 interrupted after five requests ended with a bare ^C: no statistics, no done line, nothing to say how far it got. telnet, web and udp now behave as nmap already did: the run stops, prints an ERROR interrupted attempts_completed=5 attempts_planned=100 line, the usual statistics for the attempts that completed and the done line (with --json, the one complete document, its run-level error reading interrupted: 5 of 100 attempts completed). An attempt still in flight is dropped rather than counted as a failure, and a long --delay no longer makes Ctrl+C wait. The exit status is 1 - the run was cut short, as for an interrupted nmap scan. A second Ctrl+C ends the process at once. ping still ends right away: the ping library cannot be cancelled part-way (tracked for its next upgrade). See Stopping early. (Issue #24)

v4.0.4 - 2026-09-20#

A patch release. ping gets a --timeout that works, input validation, and the payload size on every reply - three of those change what a script sees, and are in bold. udp --help stops suggesting escapes that do not work. The release process gets tighter: releases build only from a vX.Y.Z tag on main, and the Makefile becomes the one place to build and test from.

  • Fixed ping ignoring --timeout: every echo request waited a fixed one second for its reply whatever the flag said (the ping library's default was never configured). --timeout (default 5 seconds) is now how long each echo request waits before it counts as lost - pinging an address that never answers took 1.1 s for every setting before, and now takes 1.3 s, 4.0 s and 5.0 s for --timeout 1, 4 and the default. The name lookup is not covered: the ping library resolves inside its constructor with its own fixed 5-second limit. Visible effect to know about: with the default, a lost ping is now declared after 5 s instead of 1 s.
  • ping now validates its input before sending anything: --timeout must be at least 1, and --payload must be between 0 and 1448 bytes (the most one unfragmented echo request carries; the limit is read from the ping library). A larger payload used to be silently shrunk to 1448 and a negative one silently zeroed; both are now a usage error (exit status 2).
  • A lost ping echo request is now logged at ERROR level ([icmp] ERROR no reply for request #1 ...). It was logged as OK while the run exited 1; every other command already logs a failed check as ERROR.
  • ping reply lines now show the echo payload size, like the size on a real ping reply: [icmp] OK received reply for request #1 from 127.0.0.1 (ipv4) in 0ms bytes=4. bytes is the payload - what --payload sets, default 4 - not counting the 8-byte ICMP header or the IP header, so it reads like Windows ping's bytes=32; Unix ping prints payload + 8 (its 64 is --payload 56 here). The ping library records the payload it sent but not the length of the reply it read; RFC 792 requires a reply to return the request's data unchanged, so they match. A lost request has no reply to size, so its line is unchanged. The change is additive: one extra key=value at the end of the line.
  • The payload_size_bytes field in ping --json was 0 in every document; it now holds the echo payload size.
  • The shint udp --help example no longer shows --data "\x00\x00", which suggested escape sequences work. They do not: the shell passes those eight characters through and shint sends them as text (a listener received bytes=8 preview=\x00\x00, not two zero bytes). The help now shows examples that work and says plainly that backslash escapes are not interpreted; a proper way to send binary payloads (--hex) is planned for v4.2.0.
  • The release pipeline now starts only for a tag of the form vX.Y.Z (digits only) that points at a commit on main. The trigger pattern was v*.*.*, which also matched v4.0.4-rc1 and v2.2.4ae; it is now v[0-9]+.[0-9]+.[0-9]+. Every workflow's first job, verify-tag (the reusable verify-release-tag.yaml, running .github/scripts/verify-release-tag.sh), checks the name again and asks GitHub whether the tagged commit is on main; if it is not, or GitHub cannot say, it refuses and nothing is built or published. Pushing a branch (any name), pushing main or opening a pull request starts none of the release workflows. The failure-report jobs now file an issue only when lint or the vulnerability check itself failed, not when a tag was refused. The guard has an offline test, bash .github/scripts/test-verify-release-tag.sh. See CI/CD workflows.
  • The Makefile is now the one place to build and test from. make check runs everything that needs no network - gofmt, go vet, go test -race, golangci-lint (it insists on the version CI pins), govulncheck, the documentation tests and check, and the workflow checks - make test-live runs the smoke test against real hosts, and make test-full runs both. make help lists them. The release checklist, the CI documentation and the testing documentation now point at these targets. See Testing.
  • A new check, run by make check, enforces that only main runs actions: a workflow may be started only by a vX.Y.Z tag, or (for a future workflow) by a push to main that ignores .github/** - a pull_request, schedule, workflow_dispatch or branch trigger fails it, as does any trigger it cannot read. It has its own tests. See the trigger rule.
  • The live smoke test (make test-live) also checks that ping shows the payload size.
  • The issue that CI files automatically when lint or the vulnerability check fails is now accurate: its template contained ${{ ... }} expressions, which GitHub expands only in workflow files, so every issue it created showed the raw text ${{ github.server_url }}/... as its "Workflow Run URL" and named a job (lint-and-vuln-check) that no longer exists. It is now static text that points at the Actions tab. (A per-run link needs the issue body generated inside the workflow - planned with the next workflow changes.) lib/handlers/web_test.go, the last file not formatted by gofmt, is now formatted.
  • Fixed five broken links on the README front page (installation guide, usage, cookbook, troubleshooting, technical documentation): they pointed at .../shint/<page>.html, but the documentation lives under .../shint/docs/. The README also gained a Roadmap section (one release every two weeks, one at a time).
  • The documentation check (python3 docs/build.py --check) now also verifies, offline, that every published-site URL in readme.md, CHANGELOG.md and the docs sources names a page - and an #anchor - that exists, with a "did you mean" hint. It previously covered only links between generated pages, which is why the README links above went unnoticed. The generator gained tests (python3 docs/test_build.py), including one for that exact bug.
  • The release-process documentation now describes how releases are actually run: one release/vX.Y.Z branch per release, a two-week cadence with one release in flight at a time, finished work waiting on its branch until the release day, and the fast-forward-only rule the repository enforces on main. It also corrects a statement that pushing main starts nothing: it redeploys the documentation site and runs CodeQL (it starts no release workflow).
  • The shint binary that make run builds in the repository root is now git-ignored (a blanket git add would have committed it).

v4.0.3 - 2026-09-20#

  • Exit status now follows convention. A failed check used to exit 0, so if shint telnet host 22; then ... could never take the "down" branch. Now, following fping (which also checks several targets per run): 0 every check passed, 1 at least one check failed - connection refused or timed out, DNS failure, no HTTP response (a 404 or 500 is still a response), a UDP port reported closed, a lost ping, or a scan cut short - and 2 the command was used wrongly (bad argument, flag or value; nothing ran). An nmap scan that finds no open ports is a completed scan and exits 0; an inconclusive UDP open|filtered is not a failure. Usage errors are printed to stderr (previously stdout, and cobra's error was printed twice), so results on stdout stay clean. Scripts that relied on the old always-0 behaviour need updating.
  • --json stays JSON when a check fails: web records a failed attempt in stats (success: false, errors, and the bytes that did travel) instead of printing a text line in front of the document, and ping prints a JSON document, not a text line, when the lookup fails.
  • web's help text no longer claims it does not follow redirects; it does (up to 10), and counts bytes across every hop.
  • Fixed telnet reporting false failures on longer runs: --timeout was also being used as a deadline for the whole command, so once --count x --delay outlasted it (8 attempts one second apart against the default 5s), every later attempt failed instantly with i/o timeout even though the port was open. --timeout is now what each attempt (and the DNS lookup) gets, like every other command. nmap had the same flaw and is fixed the same way, below; no other command carried it.
  • Fixed nmap not scanning the whole --from..--to range: --timeout was also being used as a deadline for the entire scan, so any scan that took longer than --timeout seconds (a wide range against a host that drops packets, where every filtered port runs out its own timeout) silently stopped partway - e.g. --from 20 --to 9000 against such a host attempted about 2,000 of 8,981 ports and never reached port 5000. --timeout is now only the per-port connect timeout (as it is for every other command), and the scan runs to the end of the range. Trade-off: scans of hosts with many unresponsive ports take as long as they actually need - see the nmap page for how to estimate and speed that up.
  • nmap now reports what it actually did: ports_scanned counts ports whose probe finished (it used to count ports started), a dial aborted by cancellation is no longer recorded as a closed port, and a scan stopped by Ctrl+C says scan interrupted ports_scanned=X ports_total=Y (an error field in --json) rather than looking finished. --throttle's random per-port delay can now be interrupted with Ctrl+C.
  • nmap text output now shows how far a scan has got: a scan started line (ports_total, timeout, max_in_flight) and a progress line every 3 seconds (ports_scanned=X/Y percent open in_flight elapsed), so a long scan of unresponsive ports no longer looks hung. Quick scans print no progress lines and --json output is unchanged.
  • Documentation. A full documentation site on GitHub Pages (https://dmartsapp.github.io/shint/): installation for every platform, every command with real, captured output, the text and JSON output formats, a cookbook and troubleshooting guide, and a Technical section covering the architecture, every source file, the CI/CD workflows, the release and tagging philosophy and the testing approach. The README is now a short introduction, this changelog moved out of it into its own file, and code comments were added across the sources.
  • basic_module_test.sh (the live-internet smoke test) copes with real exit statuses: under set -e a failing command would otherwise have ended the script instead of being counted as one failed test.

v4.0.2 - 2026-09-19#

  • web and listen http now measure bytes the same way: everything on the wire, headers included, counted at the connection instead of estimated from the parsed message. v4.0.1's web figure estimated response-header size and never measured what was sent, while listen http reported body bytes only, so the two never agreed. web now reports bytes_sent and bytes_received (--json and text), summed over every hop if a redirect is followed - bytes_received replaces bytes_downloaded, and bandwidth_kbs is derived from it - and listen http's bytes_received / bytes_sent are the full request and response, so web's bytes_sent equals the listener's bytes_received and vice versa. The listener also totals both in its exit summary.
  • web --json: input_params.payload_bytes is now the request body size; it used to add the number of -H flags to it.
  • web text output: the response line no longer repeats the status three times over (response ok ... status="200 OK" is now response ... status=200).
  • listen http reads the request body before answering (it already discarded it in v4.0.1, but only after the response went out): Go's HTTP client abandons an upload that is still in progress once a complete Connection: close response comes back, so a large POST/PUT (past roughly the socket buffer - about 170KB on loopback) could be cut off partway.
  • listen http responses carry no validators (ETag/Last-Modified) and request headers are never acted on - see HTTP listener.

v4.0.1 - 2026-09-19#

  • listen tcp now measures each read (+ optional echo write) as one handled "request": text-mode data received/connection closed/done lines and JSON-mode ListenEvents report bytes_sent alongside the existing bytes_received, plus processing_time_µs (time_taken in text mode) for how long that read/echo cycle took.
  • listen http now reports bytes_received (the request body's length, now drained rather than ignored), bytes_sent (the response body's length), and processing_time_µs/time_taken for every request, in both text and --json mode.
  • Fixed web's bandwidth figure (speed in text mode, now also exposed as bandwidth_kbs in --json output): it previously added len(header) - the number of header keys, not their byte size - onto the downloaded-bytes count, understating the real transfer size and the KB/s derived from it. Both now use an actual header byte-size estimate.

v4.0.0 - 2026-09-19#

  • Full dual-stack IPv6 support. telnet, nmap, udp, web, and listen all resolve and operate over both IPv4 and IPv6 now (a dual-stack hostname is checked/scanned/pinged over both in the same run) - NetworkType changed from "ip4" to "ip". listen tcp/listen udp/listen http accept --bind :: for IPv6 (or dual-stack, platform-dependent - see Platform notes). ping already got this in the previous release via the go-ping v2.0.0 upgrade (which also fixed a data race, a payload-size clamp bug, a sequence-matching bug, and a JSON-encoding bug on the ICMP side); every other command catches up here.
  • Fixed listen tcp/listen udp/listen http exiting after exactly one connection/packet/request by default: listen's own --count now defaults to 0 (unlimited, until Ctrl+C) instead of inheriting the root --count's default of 1.
  • Fixed listen http occasionally dropping its own response (curl: (52) Empty reply from server) right as it hit its request budget - a real race between the process exiting and net/http's internal per-connection goroutine still flushing that same response. Hardened with an explicit flush, a deterministic Connection: close, and a proper Server.Shutdown wait before returning.
  • CI split from one combined workflow into five independent ones (lint, vulnerability check, binary build & release, Docker Hub, GHCR) so each has its own live status instead of one pass/fail covering everything - see the table at the top.

v3.1.0 - 2026-09-19#

  • Added listen http: a minimal JSON status endpoint (any method on / returns {"status":"ok"}, every other path 404s with {"status":"not found"}), useful for both plain TCP and HTTP-level reachability checks against the same process.
  • Docker images now publish to Docker Hub (farhansabbir/shint) in addition to GHCR.

v3.0.0 - 2026-09-19#

  • Added udp (UDP probe with open/closed/open|filtered classification).
  • Added listen tcp / listen udp local listeners for testing without a real remote server.
  • Added --cacert/--cert/--key/--insecure to web for authenticated TLS checks (custom CA trust and mutual TLS) against HTTPS services.
  • Fixed data races on the JSON stats slices in telnet and web (concurrent goroutines appending to a shared slice without synchronization).
  • Fixed a nil-pointer risk in web when given an unparseable URL.
  • Fixed web --json --withbody serializing the already-consumed request body reader instead of the payload actually sent.
  • Added input validation (port ranges, positive --count/--timeout, --from <= --to on nmap) instead of panicking or hanging on bad input.
  • Bounded nmap's concurrency so a wide port range can't exhaust file descriptors, and fixed it ignoring context cancellation during the scan loop so a slow/wide scan now actually stops at the caller's --timeout instead of running every dial out individually.
  • Unified text-mode logging across every command into one greppable format (see Logging format).
  • Upgraded to Go 1.26.3 and the latest available cobra/x-net/x-sys releases; removed stray dead config (go.env, .gitmodules) left over from an earlier private-submodule setup.
  • Expanded the release build matrix from 6 to 14 OS/architecture targets (added FreeBSD, OpenBSD, NetBSD, Solaris, Android).
  • Added a multi-arch Docker image published to GHCR on every tagged release (see Docker image).
  • Added an exhaustive, hermetic test suite (60 tests) covering both packages, including a full mTLS round trip against a locally-generated CA.
