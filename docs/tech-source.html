Source reference

Every file in the repository - what it is for, what it contains, and how it connects to the rest.

Root#

FilePurpose
main.goThe command line. Defines the cobra commands (telnet, ping, web, nmap, udp, ntp, wol, rdns, dns, cidr, ip, listen tcp|udp|http), every flag, argument validation, the exit-status scheme, and scanContext. Holds the Version constant; releaseVersion reads the release out of whatever was stamped into it, for userAgent.
main_ss.goThe ss command and its flags, built for every platform but AIX (//go:build !aix). Its init adds it to platformCommands. See No ss on AIX.
main_test.goEnd-to-end tests of the CLI. TestMain makes the test binary behave as shint when SHINT_TEST_RUN_MAIN=1, so tests run it as a subprocess and assert real exit statuses and stdout/stderr.
go.mod, go.sumThe module (github.com/dmartsapp/shint/v4), the Go version, and pinned dependencies. The go line (1.27.4) is the one place the Go release is chosen: see Moving to a new Go release.
toolchain_test.goFails when the Dockerfile's builder image is not the Go go.mod names, so the container images and the release binaries are built with the same Go.
MakefileThe one place to build and test from: cross-compilation targets for every release platform, the version-string logic for local builds, and the checks (make check, make test-live, make test-full).
DockerfileTwo-stage image build: Go build stage, distroless final stage.
.dockerignore, .gitignoreWhat stays out of the Docker build context and out of git (bin/, *.json, .DS_Store).
test/live/basic_module_test.shLive-internet smoke test: builds the binary and runs one check per command against real hosts. Run it with make test-live.
test/platforms/Platform tests: template.sh and template.ps1, the script of each release binary that platforms.py makes from them (make platform-tests; never edited by hand), and results/, the latest results from each platform (make platform-summary). test_platforms.py tests platforms.py; make check checks the scripts are current and the results add up. See Platform tests.
CHANGELOG.mdThe release history; also rendered as the Changelog page.
readme.mdThe short introduction that GitHub shows on the front page. On main it is the project README (all milestones and releases); a release branch's copy is main's (release branches up to v4.2.2 kept a working page of their own here) - see Releases and tagging.
LICENSEMIT.
index.html, .nojekyllMake GitHub Pages serve the site under docs/ as plain static files (see This documentation).

main.go in detail#

SymbolWhat it is
VersionThe version string. "4.4.0" for a source build; overridden with -ldflags "-X main.Version=..." by the Makefile, the release workflow and the Dockerfile (see Releases and tagging).
versionLine()What --version and -v print: Version, then the Go toolchain and the platform the binary was built for, in brackets, as go version writes them (runtime.Version(), GOOS/GOARCH).
flag variables (iterations, timeout, ...)Package-level variables bound to flags in init(). Shared flags live on the root command as persistent flags.
exitOK, exitFailure, exitUsage, exitCodeThe exit-status scheme (0 / 1 / 2) and the value main exits with.
usage(msg)Prints a usage error to stderr and records status 2.
finish(ok)Records status 1 when a handler reports failure.
checkRunFlags(usesDelay), checkListenFlags()The shared flag ranges, checked once for every command: --count at least 1, --timeout 1 to a day, --delay 0 to a day (lib.RequireTimeout, RequireDelay, ...); for listen, --count at least 0 and --timeout 0 to a day.
unknownSubcommandThe Run of listen and completion, which only group other commands: an argument they do not know is a usage error (exit 2), not the help page with exit 0.
rootCmd, telnetCmd, pingCmd, webCmd, nmapCmd, udpCmd, ntpCmd, wolCmd, rdnsCmd, dnsCmd, cidrCmd, ipCmd, listenCmd (+ listenTCPCmd, listenUDPCmd, listenHTTPCmd)The commands. Each Run validates, calls one handler, and passes its result to finish.
interruptContext()The context nmap, telnet, web, udp, ntp, rdns and wol run under: cancelled by Ctrl+C/SIGTERM, deliberately without any deadline, and un-registered after the first signal so a second Ctrl+C ends the process.
init()Registers all flags. Note listenCmd re-declares --count (default 0) and webCmd re-declares --payload (-P, the body), shadowing the root flags.
main()Adds the commands - and platformCommands, the ones only some platforms build - runs cobra, exits with exitUsage if cobra returned an error, otherwise with exitCode.

lib - shared code#

FileContents
lib/lib.goConstants DATETIMEFORMAT (time.UnixDate), NetworkType ("ip": A and AAAA) and Protocol ("tcp"). ResolveName and ResolveNameToIPs (DNS), IsPortUp (one TCP dial bounded by a per-attempt timeout and a context), ValidatePort, RequirePositive, GetMinAvgMax (latency statistics), ConvertIPToStringSlice, and SortTimeDurationSlice (currently exercised only by tests).
lib/descriptors_unix.go, descriptors_other.godescriptorLimit: the process's soft RLIMIT_NOFILE on Unix (Go raises it to the hard limit at start), unknown elsewhere. lib.InFlightLimit turns it into a bound on simultaneous attempts: half the limit, at most the cap, at least 4.
lib/family.goThe address family a run uses: NetworkType ("ip", "ip4", "ip6"), SetIPFamily (the -4/-6 flags), FamilyAllows, DialNetwork (tcp to tcp4/tcp6 for the HTTP client), HostFamilyConflict (an address of the other family), and FamilyHint/ExplainError (the hint on an IPv6 failure that is really this machine's lack of IPv6).
lib/output.goThe JSON contract: JSONOutput, InputParams, DNSLookup, and the per-command stats types TelnetStats, WebStats, NmapStats, ICMPStats, UDPStats, NTPStats, WOLStats, RDNSStats, CIDRStats, IPStats and IPAddress, SSStats and SSProcess, DNSStats and DNSRecord, the --timing types WebTiming and WebHopTiming, LocalJSONOutput (the document of wol, cidr, ip and ss, which have no dns_lookup), NmapJSONOutput (nmap's, whose dns_lookup is there only for one host name or address, with dns_lookups for several targets), plus the listener events ListenEvent and HTTPListenEvent. Also the text log: LogWithTimestamp (the time: [module] OK|ERROR message prefix), Fields (the key=value suffix, quoting values with spaces) and LogStats (the statistics banner).
lib/source.go--interface (#69): SetSourceInterface resolves an interface name (any case) or an address of this machine to the addresses to send from - or says what is wrong, with NoSuchInterface listing the names that exist; BindSource sets a net.Dialer's source address for each dial, of the destination's family (link-local for link-local). Every dial of telnet, nmap (IsPortUp), web, tls, udp, ntp, dns, rdns and wol goes through it.
lib/ports.goParsePorts (nmap --ports and ss --ports: numbers and ranges, sorted, each once), PortRange (--from/--to) and PortsText (a sorted list written back with runs as ranges).
lib/family_test.goThe family logic and the hint, built from the exact error a host with IPv6 disabled reported.
lib/ports_test.goWhat ParsePorts accepts and refuses (empty items, signs, words, out-of-range and backwards ranges), and PortsText round trips.
lib/lib_test.go, lib/output_test.goUnit tests for the above: validators, statistics maths, DNS (loopback, IPv6 literal, dual-stack, invalid host), IsPortUp (open, closed, IPv6, context cancellation), log formatting.

lib/handlers - one package per command#

Each command is a package of its own under lib/handlers/, holding its code, its per-platform files (_linux.go, _windows.go, ... where the systems differ) and its tests. main.go calls each package's entry point - telnet.Run, ip.Routes, listen.HTTP - and nothing else. A package depends on lib, on the shared packages in lib/handlers/internal/ below, and - for the authoritative-server lookup every resolving command prints - on dns; no command imports another otherwise.

PackageFilesWhat it holds, and what its tests cover
telnettelnet.goRun: resolve, then one connection attempt per iteration per address; true only if all succeed. Tests: success and failure output, IPv6 loopback, DNS failure, no data race, a run longer than --timeout, and Ctrl+C (telnet_cancel_test.go).
pingicmp.goRun wraps go-ping's Pinger (parallel pings, streamed lines) and converts its statistics; false on any lost ping. restrictFamily applies -4/-6; ValidatePayload. Tests: text and JSON, the payload size on replies, --timeout reaching the pinger, which lines count as lost.
webweb.go, webredact.go, webredirect.go, webtiming.goRun: builds the request, sends it through the byte-counting transport (internal/wire), reports status, timing, speed and bytes; failed attempts in JSON stats. UserAgent (set by main to shint/<release> (+URL)), ParseURL; credential redaction, the redirect policy (credentials never leave the origin), and the --timing recorder (timingRecorder, a hop per connection request). Tests: round trips and mutual TLS, redaction, redirects, timing against a fake clock and real servers, the body cap, the TLS notes in JSON, the byte-measurement guarantees against listen http and raw servers (wirebytes_test.go), and Ctrl+C.
tlschecktlscheck.goRun and Options: a handshake per address with the TLS versions shint offers (tlsMinVersion..tlsMaxVersion, shown as offered=), the chain verified against the name (verifyChain), expiry judged on the verified chain, errors in plain words (explainTLSError). Tests: trusted, untrusted, expired and wrong-name chains, --warn-days/--fail-days, servers limited to TLS 1.2 or to TLS 1.0-1.1.
nmapnmap.go, nmaptargets.go, nmapservices.goRun, given a Scan (targets and ports): looks up each host name, sweeps each prefix, scans each address once, writes an NmapJSONOutput; a sweep of public addresses gets publicWarning and probes spaced by Scan.Delay (#106). ParseTargets checks every target first (a host name's shape, families, a prefix's size, 65,536 addresses at most); isPublicSweep, sweepAddresses; tcpServices behind service=. Tests: open ports on IPv4 and IPv6, the concurrency cap and the descriptor limit, whole-range coverage, interruption, progress lines, port lists, several targets, sweeps and their pace.
udpudp.goprobeUDP (open / closed / open|filtered / error) and Run; ValidatePayload, ParseHexPayload. Tests: each state, generated payloads, multiple attempts, Ctrl+C.
ntpntp.goRun and queryNTP: one SNTP v4 query per address; NTP's 64-bit timestamps with the 2036 wrap; the 48-byte request and the replies it refuses. Tests: a controllable fake SNTP server (offsets, processing time, malformed replies, timeouts, IPv6), Ctrl+C.
wolwol.goRun, MagicPacket (6 x 0xFF and the MAC 16 times), ParseMAC, ParseBroadcast. Tests: the packet received by a real UDP socket, Ctrl+C.
rdnsrdns.goRun; lookupAddr, the resolver call, a variable so tests substitute it (Go's resolver, bound to --interface when given). Tests: a substituted resolver, Ctrl+C.
dnsdns.go, authoritative.goRun, ParseArgs and Options: the DNS client (golang.org/x/net/dns/dnsmessage; UDP with EDNS, TCP on truncation or --tcp; the hosts file first); ReverseName (the in-addr.arpa./ip6.arpa. name). FindAuthoritative, PrintAuthoritative and AuthoritativeTimeout: the zone and name servers every resolving command shows, asked in parallel through the same client. Tests: a fake DNS server on loopback (every record type, negative answers, truncation and retry, EDNS fallback, wrong IDs), the authoritative lookup's cases.
cidrcidr.goRun and ParseSubnets: subnet arithmetic with net/netip and math/big. Tests: values worked out by hand and checked against net.ParseCIDR.
ipip.go; iproute.go, iproute_proc.go, iproute_win.go, iproute_{linux,bsd,bsd_darwin,bsd_other,windows,other}.go; iparp.go, iparp_netlink.go, iparp_win.go, iparp_{linux,bsd,windows,other}.goInterfaces (the interface table behind systemInterfaces), InterfaceNames and noSuchInterface. Routes: the routing table from readRoutes, or the way to an address (kernelRoute, a UDP connect; matchRoute on the system's interface only). Neighbours: the neighbour table from readNeighbours, the default gateways marked. The parsers (/proc, netlink messages, Windows rows) have no build tag and are tested everywhere; platformRoutes/platformNeighbours per system. Tests: fake interface tables, /proc in both byte orders, macOS's flag combinations, lookups, netlink and Windows rows built byte by byte, unknown interfaces.
ssss.go, ssproc.go, sswin.go, ss_{linux,windows,other}.goRun and Query: the sockets from readSockets, the filters, the sort order, the text line, the owners hidden warning. Linux: /proc/net/{tcp,tcp6,udp,udp6} and /proc/<pid>/fd; Windows: GetExtendedTcpTable/GetExtendedUdpTable rows and a process snapshot. Tests: text and JSON, every filter, a fake /proc, Windows tables built byte by byte.
listentcplisten.go, udplisten.go, httplisten.go, listennotice.goTCP, UDP and HTTP: the listeners; httpExchange records the request each connection served, reported on close so byte counts are final; exposureNotice (the reachable from other machines warning). Tests: accept and echo, IPv6, JSON events and their measurements, runs until interrupted.

Shared packages#

PackageFilesWhat it holds
lib/handlers/internal/pacepacing.go, interrupt.goHow a repeating check runs and ends: Slots (at most 500 attempts in flight, fewer under a low descriptor limit), Delay (--delay/--throttle), Pause (a delay Ctrl+C cuts short), WatchCancel (a cancellation unblocks a read), InterruptedLine/InterruptedNote. Tested.
lib/handlers/internal/termescape.goText that is safe to print and short to read: Escape (untrusted bytes - a packet, a DNS record, a process name - escaped), Preview (trimmed and cut, for listeners and udp), and the plain-words error helpers Reason, ShortError, UnwrapPath. Tested.
lib/handlers/internal/wirewireconn.goByte counting on the wire, shared by web and listen http: Conn (BytesRead, BytesWritten, FirstWritten, SetOnClose), Listener, NewTransport (an HTTP/1.1 transport whose plain and TLS connections are counted) and Meter (a request's share of a connection).
lib/tlsconftls.goBuild: --cacert, --cert/--key and --insecure as a tls.Config (TLS 1.2 at least); LoadCAPool. Used by web and tls. Tests: every branch.
lib/internal/testutiltestutil.go, interrupt_{unix,windows}.goWhat the tests share: CaptureStdout (stdout through a pipe drained concurrently), FreeTCPPort, FreeUDPPort, a throw-away certificate authority (NewCA, IssueCert, WritePEM), echo listeners, WaitForListener, UseFamily, MustContain, CancelAfter/InterruptedCounts/RunWithin for the Ctrl+C tests, and SendInterrupt/RequireInterrupt (SIGINT to the test process; skipped on Windows). Used only by _test.go files.

Build and packaging#

FilePurpose
MakefileOne target per platform (linux-amd64, darwin-arm64, ...), the groups linux/darwin/windows/..., all (the desktop triad), all-platforms (every release target), run, clean. Builds with CGO_ENABLED=0 -trimpath -ldflags "-s -w -X main.Version=...". It also holds every check: check, test, test-live, test-full, fmt-check, vet, lint, vuln, docs-check, workflows, tools and help (see Testing).
DockerfileStage 1 golang:1.27.4-alpine (the Go go.mod names - toolchain_test.go keeps the two the same) compiles the binary for TARGETOS/TARGETARCH; stage 2 gcr.io/distroless/static-debian12:nonroot carries only the binary and CA certificates. ENTRYPOINT ["/shint"], CMD ["--help"].
.dockerignoreKeeps .git, .github, bin, markdown files and scripts out of the build context.

Continuous integration#

FilePurpose
.github/workflows/verify-release-tag.yamlThe tag guard, a reusable workflow every other workflow calls first: the tag must be vX.Y.Z and its commit must be on main. No trigger of its own.
.github/scripts/verify-release-tag.shThe guard's checks (tag format, then the GitHub compare API).
.github/scripts/test-verify-release-tag.shOffline tests for the guard, with a fake gh: bash .github/scripts/test-verify-release-tag.sh.
.github/scripts/check-workflow-triggers.pyFails if any workflow can be started by anything other than a vX.Y.Z tag (or a push to main that ignores .github/**). See the trigger rule.
.github/scripts/test_check_workflow_triggers.pyTests for that check, including a run over the real workflow files.
.github/workflows/lint.yamlGuard, then golangci-lint; opens an issue on failure.
.github/workflows/vulncheck.yamlGuard, then govulncheck with a step summary; opens an issue on failure.
.github/workflows/build.yamlGuard, gate, then 14 cross-builds (each attested and given a .sha256 file), then the GitHub Release with the binaries and checksum files attached.
.github/workflows/docker-hub.yamlGuard, gate, then a multi-arch image pushed to Docker Hub.
.github/workflows/ghcr.yamlGuard, gate, then the same image pushed to GitHub Container Registry.
.github/workflows/check.yamlAfter a merge to main (never a branch, PR or tag; ignores .github/**): make check-quick when a valid signed local check report is on the commit, the whole make check when it is not; opens an issue on failure.
.github/scripts/changelog-section.shPrints one release's section of CHANGELOG.md: the release page's "What's new" (with test-changelog-section.sh).
.github/scripts/attest.shmake attest: runs make check, builds and signs the report, attaches it to the commit as a git note (refs/notes/checks) and pushes the note.
.github/scripts/check-report.pyBuilds the report from make check's output, signs it with ssh-keygen -Y sign, and verifies a note (signature, tree, every stage, age). Standard library only.
.github/scripts/test_check_report.pyIts tests, with throw-away SSH keys: a valid report, and each way one is refused.
.github/scripts/verify-local-check.shThe Check workflow's side: fetches the note and the allowed signers (from the commit before the push) and asks check-report.py. Writes fast=true/false; never fails.
.github/scripts/test-attest.shTests for attest.sh, the verifier and the hook, in throw-away repositories.
.githooks/pre-pushInstalled by make hooks: pushing main or a release tag with no valid signed report runs make attest first.
.github/allowed_signersThe public keys whose signed reports CI accepts (namespace shint-check).
.github/workflows/readme-reconcile.yamlAfter a release tag, once the GitHub Release exists: proposes main's README for it (a branch and a pull request, or an issue that links the branch). Never commits to main.
.github/scripts/readme-reconcile.pyBrings a README in line with the release tags, the changelog, the milestones and the binary's --help, puts back what it must always have (expansion, badges with the donate button, support line), warns about what it cannot know; idempotent, fails closed.
.github/scripts/test_readme_reconcile.pyIts tests, on README fixtures (35 of them).
.github/scripts/readme-release.shmake readme-reconcile: branches readme/main-<tag> off main, runs the script, commits, and with PUSH=1 pushes and opens the pull request.
.github/scripts/test-readme-release.shTests for it, in throw-away git repositories with a fake gh.
.github/scripts/release-check.shmake release-check, run by make release after the release commit: on top of main, readme.md changing only main's Roadmap rows (with this release's row Released), releases/vX.Y.Z.md present, the version, dated changelog and release-commit message agreeing, no attribution trailers, the tag free.
.github/scripts/test-release-check.shTests for it, in throw-away git repositories.
.github/scripts/release.pymake release-start and make release: starts a release branch with its changelog heading and working page, and on release day stamps, checks, commits and - after one confirmation - pushes main, waits for Check, tags and verifies the release; resumable (Making a release).
.github/scripts/test_release.pyTests for it, end to end: a bare origin, a clone, the real reconcile and release-check scripts, and a fake gh.
branch_readme.mdOn a release branch only: its working page - targets, bugs, changes, the To do list, and the Summary: that becomes the release's roadmap row. make release refuses to publish while a to-do is unchecked and moves it to releases/vX.Y.Z.md.
releases/vX.Y.Z.mdA release's record on main: its working page, as it was when it shipped. See releases/.
.github/scripts/write-checksums.shWrites <binary>.sha256 next to each release binary and verifies it.
.github/scripts/test-write-checksums.shOffline tests for it: format, an independent hash, the platform's own verifier, tampering.
.github/scripts/write-ci-failure-issue.shWrites the body of the issue a failed check files, with the real run URL.
.github/scripts/test-write-ci-failure-issue.shOffline tests for it.

Each workflow is explained in CI/CD workflows.
