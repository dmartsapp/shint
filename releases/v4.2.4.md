## Other changes

- **golangci-lint v2.13.2 -> v2.15.0** (`Makefile`, `check.yaml`, the four release workflows), forced by the Go upgrade: Go 1.27.3 writes compiled packages in export data version 5, which v2.13.2's `golang.org/x/tools` cannot read. v2.15.0 found one unchecked error, in `listen http`'s shutdown, now checked (no change in practice). Part of [`dac550f`](https://github.com/dmartsapp/shint/commit/dac550f).
- **`toolchain_test.go`** fails when the `Dockerfile`'s builder image and `go.mod` name different Go releases, so the images and the binaries cannot drift apart.
- **Docs:** the Go version comes from `go.mod` through a `{{go}}` token instead of being typed on four pages; [Moving to a new Go release](https://dmartsapp.github.io/shint/docs/tech-ci.html#moving-to-a-new-go-release) is the procedure; the dependency table is corrected (go-ping v2.0.1; x/net is a direct dependency, for `dns`).
- **Not here:** `github.com/dmartsapp/go-ping`'s own `go.mod` still names x/net v0.59.0 and Go 1.27.1. shint builds with the newer x/net either way; go-ping itself is updated with the v4.4.0 go-ping work.

## After the release, on `main`

None of this is in the tagged release, and none of it changes the binary.

- **How the release went**: two stops, both outside the project, neither a fix. The first `make release` stopped at the live smoke test - one of `time.cloudflare.com`'s four NTP addresses refused a query, and answered again half a minute later - and took its release commit back off, as designed; the second run published. Then Binary Build & Release and GHCR Release failed in their gate: GitHub's release downloads answered `504` for golangci-lint's binary (and every other project's release assets) for about 20 minutes; their failed jobs were rerun once the downloads worked, and passed. Check on `main` passed on the release commit ([`82e7bfb`](https://github.com/dmartsapp/shint/commit/82e7bfb)) with the full suite - `make release` ran without `make attest`, so there was no signed report. Docker Hub was published first, the binaries and GHCR about 25 minutes later.
- **Verified**: 36 assets, as for v4.2.3; the darwin/arm64 binary's checksum and build attestation verify, and it reports `v4.2.4/82e7bfb.../2026-11-08T09:38:57+0000 (go1.27.3 darwin/arm64)`; Docker Hub and GHCR have `4.2.4`, `v4.2.4`, `4.2`, `4` and `latest`.
- **A security and support policy**: [`SECURITY.md`](../SECURITY.md) and the documentation's [Security](https://dmartsapp.github.io/shint/docs/security.html) page, with this release's advisory - each vulnerability's Go vulnerability database record and CVE number, the Go project's issue, fix and announcement, how shint was affected, and what was done ([`539433e`](https://github.com/dmartsapp/shint/commit/539433e)); a Security section in the README ([`e5ccdea`](https://github.com/dmartsapp/shint/commit/e5ccdea)).
- **Closed**: [#91](https://github.com/dmartsapp/shint/issues/91), then milestone v4.2.4; [#92](https://github.com/dmartsapp/shint/issues/92), Check's automatic report for the README commit `make release-start` pushed to `main` while it was still on Go 1.27.1.
